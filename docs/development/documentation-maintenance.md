# 文档维护边界

## 文档定位

本文约束 `docs` 下当前维护文档、阶段性计划、发布追溯、规则补充和过期文档的读取、修改和新增边界。所有任务仍必须先遵守根目录 `AGENTS.md` 与 `docs/AGENTS.md`。

## 文档分区

| 分区 | 用途 | 是否可作为当前约束入口 |
| --- | --- | --- |
| `docs/AGENTS.md` | 文档体系总入口、阅读顺序、模块索引 | 是 |
| `docs/architecture/` | 当前架构、层边界、不变量、ADR | 是 |
| `docs/development/` | 当前开发、测试、构建、文档维护规范 | 是 |
| `docs/domain/` | 当前领域行为、API、平台差异、模板契约 | 是 |
| `docs/modules/` | 当前模块职责、禁止事项、三态 checklist | 是 |
| `docs/operations/` | 当前部署、监控、内存、故障处理 | 是 |
| `docs/context/` | 当前状态、已知问题、术语 | 辅助入口 |
| `docs/release/` | 项目所有者维护的版本发布说明 | 仅用于版本追溯 |
| `docs/plans/` | 阶段性设计、实施计划、测试报告 | 否，除非任务明确要求执行该计划 |
| `docs/规则/` | 专项规则补充或历史迁移规则 | 否，必须由当前入口文档显式引用后才可作为约束 |
| `docs/过期文档/` | 过期分析、历史报告、旧方案 | 否，只能作为历史背景 |

问题台账分工：`docs/bugs.md` 记录实现、架构约束与文档之间的工程偏差、状态和收敛条件；`docs/context/known-issues.md` 记录运行人员可见的症状、影响与临时绕过。确认或关闭问题时必须同步关联 BUG/KI 条目。

## 读取规则

- 查询当前实现时，优先读取 `docs/AGENTS.md`、模块文档、架构/领域/运维当前文档。
- 查询根目录说明、授权、忽略规则或示例环境变量时，优先读取 [`repository-files.md`](repository-files.md)。
- 查询版本历史时可以读取 `docs/release/`，但 release 文档不得覆盖当前模块、架构、开发或运维约束。
- 读取 `docs/plans/` 前，必须确认用户正在要求执行、审查或追溯某个计划。
- 读取 `docs/规则/` 前，必须确认当前维护文档显式引用该规则，或用户明确要求。
- 已迁移到当前维护文档的规则，应优先读取迁移目标；例如 Skiko 对象生命周期以 [`skiko-object-lifecycle.md`](skiko-object-lifecycle.md) 为准，`docs/规则/Skiko 对象生命周期管理总表.md` 只保留历史来源。
- 读取 `docs/过期文档/` 前，必须说明它只用于历史背景，不能覆盖当前维护文档。

## 修改规则

- 当前约束变更应写入 `architecture`、`development`、`domain`、`modules` 或 `operations`，不得只写入 `plans`。
- 阶段性方案、执行记录和一次性测试报告应写入 `plans`，并在落地后把长期约束提炼回当前维护文档。
- `docs/release/` 由项目所有者维护；AI 不得修改、新增或删除 release 文档，除非用户在当前对话中明确要求。
- 版本用户可见变化需要进入 release 时，只能在交付说明中提醒项目所有者补写，不得用 release 文档替代模块约束。
- 过期文档原则上只追加“已过期原因”和迁移指向，不得在其中维护新的当前规则。

## 新建规则

- 新增当前模块约束时，优先新增或更新 `docs/modules/*.md`，并同步更新 `docs/AGENTS.md` 模块索引。
- 新增根目录维护文件约束时，优先更新 [`repository-files.md`](repository-files.md)，并同步检查 `docs/AGENTS.md` 模块索引。
- 新增架构决策时，使用 `architecture/decisions/adr-*.md`，并在不变量或层边界中引用。
- 新增计划时，文件名使用日期前缀，并明确哪些内容是临时执行步骤，哪些需要落地后迁移为长期约束。
- 新增 `docs` 分区前，必须先说明既有分区无法承载的原因，并更新 `docs/AGENTS.md` 与本文档分区表。
- 新增过期归档时，必须保留原文，不得删除历史注释或结论；若内容会误导当前维护，应在当前文档中给出替代入口。
- `.gitignore` 必须允许 `docs/AGENTS.md`、`docs/bugs.md` 和当前维护分区新增文件进入版本控制；`plans`、`规则` 与 `过期文档` 继续保持忽略，除非项目所有者明确改变分区策略。

## 查询 checklist

- [ ] 是否确认要读取的是当前约束、阶段计划、发布追溯还是历史背景？
- [ ] 是否确认 release 文档只用于版本追溯，不用于覆盖当前约束？
- [ ] 是否避免从 `docs/plans/`、`docs/规则/` 或 `docs/过期文档/` 直接推断当前实现？
- [ ] 是否优先选择模块文档和当前架构/领域/运维文档？

## 变更 checklist

- [ ] 是否把长期约束写入当前维护分区，而不是只写入 plans？
- [ ] 是否同步更新 `docs/AGENTS.md` 的阅读入口、模块索引或三态入口？
- [ ] 是否避免修改、新增或删除项目所有者维护的 release 文档？
- [ ] 是否保留既有注释、历史结论和迁移指向？
- [ ] 是否检查链接仍指向当前维护文档？

## 新建 checklist

- [ ] 新文档是否有明确分区和维护状态？
- [ ] 新文档是否说明它是当前约束、阶段计划、发布说明还是历史记录？
- [ ] 新当前约束是否被 `docs/AGENTS.md`、模块文档或相关入口引用？
- [ ] 新分区或新入口是否已先更新 `docs/AGENTS.md` 和本文档分区表？
- [ ] 新历史或计划文档是否避免覆盖当前维护文档的权威性？
