# 模块文档模板

复制本模板创建新模块文档时，保留所有小节并删除不适用项。模块文档必须描述“当前实现”，不要写未落地的目标状态。

## 模块定位

说明该模块解决什么问题、属于哪一层、上游和下游是谁。

## 代码入口

- `src/main/kotlin/...`
- 关键类或 object
- 关键测试

## 主要职责

- 职责 1
- 职责 2
- 职责 3

## 禁止事项

- 禁止项 1：说明原因。
- 禁止项 2：说明原因。

## 关键流程

按调用顺序描述核心运行流程。必要时引用架构文档、ADR 或系统不变量。

## 资源与生命周期

说明该模块是否拥有协程、文件、网络客户端、native 资源、缓存、channel 或全局状态，以及释放方式。

## 配置与数据

说明该模块读取或写入哪些配置、数据结构和文件。若不写配置，也要明确“不拥有写入权”。

## 测试与验证

列出修改该模块后应运行的测试或检查命令。

## 查询 checklist

- [ ] 是否阅读根目录 `AGENTS.md` 与 `docs/AGENTS.md`？
- [ ] 是否确认查询对象属于本模块，而不是相邻模块或历史计划？
- [ ] 是否阅读本模块指向的 architecture、domain、development 或 operations 文档？
- [ ] 是否区分当前实现、计划中设计和过期文档？

## 变更 checklist

- [ ] 是否阅读根目录 `AGENTS.md`？
- [ ] 是否保留现有注释并延续注释风格？
- [ ] 是否需要同步 KDoc？
- [ ] 是否需要更新红线、不变量、ADR 或上下文文档？
- [ ] 是否运行了对应测试？

## 新建 checklist

- [ ] 新文件是否优先归入已有模块？
- [ ] 新函数、方法或逻辑块是否补充紧邻注释说明用途、意图或关键约束？
- [ ] 新资源、协程、客户端、缓存、channel 或 native 对象是否有生命周期说明？
- [ ] 新配置、数据结构或外部接口是否更新对应 domain、development 或 operations 文档？
- [ ] 新模块是否同步新增 `docs/modules/<name>.md` 并更新 `docs/AGENTS.md` 模块索引？
